# ADR-0045: Bounded warp32 Tensor reference recovery

Status: Proposed (2026-10-24). Documentation only; execution is not authorized.

## Context and retained stop

[ADR-0044](ADR-0044-tensor-cost-continuation.md)'s frozen device cohort passes
66 ordinary GPU tests, 280 product comparisons and range refusal, then fails its
first INT8 controller comparison after 64 logical / 66 physical updates and
two audits. The device audit's `tc_ref_product` sums entries serially. The host
`precision::product` uses lane-strided warp32 sums and a fixed reduction tree.
The resulting 1–4 ulp endpoint differences violate the required bitwise
controller comparison even though the observed controller decisions agree.
This is an implementation defect, not evidence that a tolerance should change.

The [retained failure report](../benchmarks/lp-tensor-cost-device-gpup8.md) and
[machine report](../benchmarks/data/tensor-cost/device-refusal-v1.json) remain
historical and immutable. No fixed-work/replay pair, sanitizer, profile or primary
timing followed the failure. All 76 old study identities remain unexecuted.
Neither accepting this proposal nor creating new identities erases that stop.

The user requests a bounded proposal without host access or changes to numerical
or latency completion criteria. Acceptance of this ADR would authorize exactly
one corrected source cohort and one new sequence of gates/study, as an explicit
exception to the previous stop. It would also reopen and reallocate the closed
CPU stages described below. Existing unused totals alone authorize neither.

## One correction, with the existing reference arithmetic

Create `artifacts/gpup-tensor-warp32-v1` and a separate recovery source tree.
Preserve the failed source tree and image byte-for-byte. In the recovery copy,
change only the body of the device reference sparse-product reduction:

1. Initialize 32 FP64 lane accumulators exactly as the host reference does.
   Lane `l` visits entries `first + l, first + l + 32, ...` in stored order.
2. Use separately rounded FP64 multiply/add operations and the same finite and
   underflow checks as the host. Combine lane sums in the host's exact
   `16, 8, 4, 2, 1` order, with the same active-lane operations at each stage.
3. Keep the existing kernel ABI, sparse indexing, output ownership and launch
   shape. Implement these arithmetic lanes within the existing output thread
   using explicitly unrolled accumulators/tree operations. No new cross-warp
   synchronization or launch scheduling is needed.

This is one prescribed construction. Compile and inspect it before device
admission: at most 128 registers, zero spills, the existing FP64 rounding flags,
and the same required Tensor instructions for the represented-product kernels.
If scalarization fails the resource gate, stop on CPU; there is no automatic
alternative construction or tuning sweep.

Keep the norm bound, represented products, tiny-value FP64 residual corrections,
state, controller, audit cadence, guards, sticky promotion and whole-window
replay unchanged. Other reference kernels and all host numerical bodies must
match the failed frozen source byte-for-byte. Use the unchanged host executable
and existing code-object loading interface with the corrected image in a
separate frozen directory. Record and check the resolved image path/hash;
fallback to an old image refuses. If this cannot be done through the existing
interface, stop before device execution rather than expanding the repair.

## CPU acceptance before device work

Retain the accepted in-container supervisor and its successful bootstrap.
Do not rerun bootstrap or change supervisor/admission code. Reuse its inherited
four-CPU mask, serialized top-level phases, descendant accounting and cleanup,
durable completion transport, sampling/stop rules and conservative four-times-
wall charging. Every wait, monitor, verifier and termination interval counts.
Keep the 8-GiB aggregate RSS policy, 6-GiB stop threshold, 2-GiB numerical
preparation, 1-GiB device buffers and 32-GiB combined-artifact ceiling.

Before any lease:

- Cross-check an independent reduction oracle against the actual host reference
  and the recovery kernel's host-testable arithmetic. Cover empty/tail lines,
  31/32/33 and 63/64/65 entries, multiple stride rounds, CSR and CSC order,
  cancellation, signed zero, small values, and overflow/underflow refusal.
  Include `[1e16, 1, -1e16, 1]` with unit multipliers: the prescribed tree gives
  2 while the defective serial order gives 1. Compare bits and refusal behavior;
  exact-real agreement alone is insufficient.
- Retain the previous unchanged norm/layout/component proofs with a strict
  source bridge. Run the complete eight-model CPU admission cohort under the
  supervisor, binding its new records to the recovery source/image and unchanged
  host executable. Independently verify new retained endpoints, including
  available failed/interrupted endpoints. Do not rerun historical CPU cohorts.
- Prepare and test the new harness/report reader, aggregate budget admission,
  refusal paths and endpoint-verification receipts before freezing. Run
  `bash tools/check.sh` once, including the 26 resource regressions, applicable
  historical source-bridge checks, Rust/native/dependencies, Python, replay,
  docs and smoke, with CUDA hidden. The retained complete gate charged
  1069.880040068 CPU seconds; reserve 1200 for this gate. This is sizing evidence,
  not a guarantee under shared-server contention.
- Freeze exact source/image/executable hashes, all 76 study cells, six acceptance
  jobs, request schemas, job order, commands, stage limits and forecast/report
  rules. A command/source mismatch or a real failure stops this continuation.

No cgroup, host, Kubernetes, privilege, system-service or container configuration
change is involved. Do not inspect or signal unrelated users' processes. Wait
only through the existing allocator's bounded admission; a busy device may
refuse. Do not substitute devices.

## Unchanged completion and stop rules

Retain the 1e-7 local budgets, 1e-9 original-model host certification, resident
FP64 state, explicit tiny-value corrections, charged whole-window replay and
uniform sticky promotion. Every fresh solve still performs its required fresh
host assessments/certification. Receipt reuse avoids duplicate report-time
verification; it never replaces a solve's certification.

Completion still requires every software/numerical/device/resource gate; useful
INT8 and at least one FP16/BF16 nontrivial certified solve; all five repetitions
certifying with no coverage loss against tuned on either timing model; and at
least one paired total-latency bootstrap speedup interval excluding one after
Bonferroni adjustment across all six comparisons at 95% family confidence,
10000 resamples and seed 17002. Independently verify every retained endpoint,
including available failed/interrupted records. Native promotion, residual-only
work, host-only initial certificates, forecasts and microbenchmarks cannot win.

A CPU/resource admission failure, incorrect bit, missing required gate, timeout,
sanitizer finding, unavailable forecast, exhausted cap or absence of an adjusted
certified total-latency gain ends this continuation with GPUP-8 incomplete.
No automatic repair, second image, device substitution, new cells, retries,
GPUP-9 or preset follows. Even a gain cannot complete GPUP-8 without the full
prospective resource cohort. Do not reinterpret historical resource overlap
as certified. Local commit follows applicable acceptance; publication and merge
remain outside scope.
