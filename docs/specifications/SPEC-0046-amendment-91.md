# SPEC-0046 amendment 91: certification utilization optimization

Status: authorized development, 2026-11-23. Owner: numerical backend.
Last reviewed commit: 8035ee7. The user says: "Go ahead to your optimization
scope. I also wonder if it is a good idea to put the certification on GPU."
This opens the versioned optimization scope proposed in the
[utilization diagnosis](../benchmarks/lp-billion-utilization.md). Prior no-work
instructions retain their historical scope; completed studies never reopen.

1. Preserve all historical images, manifests, outcomes, failures and full charges.
   Retain exact pre-change sources before changing the current isolated research
   executor. Never repeat an attempted scientific identity or completed driver.
2. Keep public defaults, tolerances, original-model CPU authority, outward
   arithmetic, control100/certificate500, deadline rollback and all physical,
   ownership, sampling and resource ceilings unchanged.
3. First implement opt-in CPU certificate scratch reuse with the identical
   1024-leaf reduction tree, signed-zero normalization, refusal behavior and
   original column order. No retained graph proportional to matrix nonzeros.
   Assess work-balanced contiguous partitions only if CPU evidence justifies it.
4. Final-assessment reuse must be local to one solve and match exact state
   identity including rollback generation; repaired-dual evidence and termination
   status remain exact. No independent final proof may be removed.
5. GPU screening may propose work and rejection, but may not establish a bound
   or successful solve without the original independent CPU proof. This scope
   evaluates the GPU opportunity; it does not replace ADR-0010's authority.
6. Require source-bound CPU36, a fresh sustained idle observation and GPU28
   before device development. Use fresh identities and retained complete CPU
   differential tests before any candidate device admission. Exact continuations
   must cover rollback/cancellation and both settings of the new option.
7. Bound this slice within the existing totals and exact phase caps: CPU admission
   6000, native 2400, development 12000, reporting 6000, cleanup 240 seconds;
   GPU admission 800 and development 2400 seconds. These are maxima, not new
   allowances. Check the complete remaining envelope before work. Retain every
   failure/full reservation; no overrun exception is introduced.
8. Run one dependency-ready slice at a time. Start with CPU proof/implementation;
   stop device release if CPU equivalence fails, capacity is unavailable or
   operational guards refuse. The existing 0.9-second inventory timeout and
   one-second sampling limit remain unchanged.
9. Report actual tests, cold/complete phase costs, regressions and unknowns.
   CPU microbenchmarks cannot establish solver utilization or certified-solve
   speedups. No publication or public adoption is authorized by this scope.

Implementation: isolated `research/lp-billion-lowbit` checker and opt-in solver
wiring; new utilization tools, tests and report. Acceptance: exact scalar and
enclosure comparisons, first-refusal tests, scratch growth/reuse, source-only
configuration tests, isolated native quality, then operational/candidate device
checks when admitted. A storage-preflight refusal starts no workload and must
remain visible; it cannot be bypassed by an unguarded test invocation.
